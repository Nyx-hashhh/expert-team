# 文案规则库两阶段工作流

本目录服务于两次彼此独立、前后衔接的 API 调用。第一阶段在 `idea` 中把简短宣发诉求转成可人工修改的结构化思路；第二阶段在 `post` 中把已经确认的思路写成适配品类、平台和语调的最终文案。两个阶段不得混写，也不得在一次调用中读取另一阶段的全部规则。

## 总流程

`简短诉求 + 企业真实素材 → idea 生成四字段思路 → 人工确认或修改 → post 生成平台正文 → 成稿校验`

两阶段唯一的交接物是：

- 所选思路模式：故事型、种草型或品牌型。
- 已确认的四字段思路：核心宣发受众、核心表达、内容切口、开场钩子。
- 与本次任务有关的企业真实素材及缺失项。

平台、语调、正文结构和 A/B 版本只在第二阶段处理。第一阶段不得提前写正文，第二阶段不得擅自推翻已确认的思路。

## 第一阶段 idea 从简短输入到思路

### 输入

- 用户的一句话或少量关键词诉求。
- 所选思路模式。
- 本次勾选的企业真实素材；未提供的信息视为缺失，不得补造。

### 工作顺序

1. 读取 [idea 阶段说明](idea/README.md)。
2. 按 [从简短输入到思路大纲的实操方法论](idea/01-methodology/from-brief-to-outline.md) 完成通用推导。
3. 只读取 [02-modes](idea/02-modes/) 中与所选模式对应的一个文件，补充该模式的推导重点。
4. 输出四个备忘录式短字段，交给用户确认或修改。

### 输出

只输出以下四项，不生成标题、段落正文、平台版本或 A/B 版本：

```text
核心宣发受众：...
核心表达：...
内容切口：...
开场钩子：...
```

## 第二阶段 post 从思路到最终文案

### 输入

- 所选思路模式和已确认的四字段思路。
- 本次任务所需的企业真实素材。
- 目标平台、表达语调和版本要求。

### 工作顺序

1. 读取 [post 阶段说明](post/README.md)。
2. 读取 [01-foundation](post/01-foundation/) 固定真实性、证据与正文边界。
3. 只读取 [02-categories](post/02-categories/) 中当前品类及当前模式对应的文件。
4. 只读取 [03-platforms](post/03-platforms/) 中目标平台对应的文件。
5. 只读取 [04-tones](post/04-tones/) 中所选语调对应的文件。
6. 使用 [05-composition](post/05-composition/) 合成正文并完成终检。

### 输出

按目标平台分别生成可发布正文；需要 A/B 版本时，两版共享已确认的思路和事实底座，只改变正文切入、证据顺序、场景或互动方式。

## 按需读取规则

- `idea` 调用不得读取 `post` 的平台、语调、正文组合规则。
- `post` 调用不得重新运行 `idea` 的思路推导流程。
- 一次任务只读取一个模式、一个品类、所选平台和一个语调对应的规则，不读取同级无关文件。
- 真实性与证据边界始终有效；素材缺失时标记缺口或降低表述强度，不得用想象补齐。

## 快速示例

输入“高山春茶，新品上市，想突出送礼和品质感”，选择种草型后，`idea` 先给出四字段思路并由用户确认。确认后，`post` 再结合农产品证据、小红书结构和闺蜜安利语调生成正文。第一阶段回答“写什么思路”，第二阶段回答“怎样在目标平台写成文案”。
