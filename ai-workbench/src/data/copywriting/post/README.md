# post 阶段 从已确认思路到最终文案

`post` 是第二次 API 调用，职责是接收用户已经确认的思路大纲，并根据品类、平台和语调写成可发布正文。它不重新发散思路，也不擅自改变四字段中的核心方向。

## 输入合同

- 所选思路模式：故事型、种草型或品牌型。
- 已确认的四字段思路：核心宣发受众、核心表达、内容切口、开场钩子。
- 本次任务所需的企业真实素材及证据状态。
- 目标平台、表达语调和版本要求。

若四字段缺失或彼此冲突，先指出缺口并请求确认；不得自行重新运行第一阶段。企业素材不足时降低表述强度或列出待补信息，不得虚构。

## 执行顺序

1. [01-foundation](01-foundation/)：固定真实性、证据、素材和通用输出边界。
2. [02-categories](02-categories/)：只读取当前品类及当前模式的细化规则。
3. [03-platforms](03-platforms/)：只读取目标平台的结构、语种和互动规则。
4. [04-tones](04-tones/)：只读取所选语调的语言参数。
5. [05-composition](05-composition/)：合成正文、处理冲突并完成终检。

正文优先级为：

`真实性与安全 > 已确认思路 > 品类证据 > 平台结构 > 表达语调 > 热点与修辞`

## 输出合同

- 每个目标平台单独输出，遵守其语种、长度和结构。
- 核心表达、关键事实和适用边界在多平台间保持一致。
- A/B 两版共享同一思路和事实底座，至少改变切入场景、证据顺序、正文结构或互动方式中的两项；不得只替换标题和形容词。
- 输出前使用成稿检查表核验事实、平台格式、语言自然度和风险边界。

本阶段的上游交接规范见 [idea 阶段](../idea/README.md)。
