# 种草型思路转译

## 任务目标

将工作台用户填写的【核心宣发诉求】与本次勾选的【企业素材库】，转为供下游写手扩写的种草型思路大纲。只输出 **核心宣发受众、核心表达、内容切口、开场钩子**，让受众看出产品或体验与自己的需求有什么关系、值得关注哪个具体细节。不写正文、段落安排或平台玩法。

种草型可以从一个实际麻烦切入，说明产品如何回应它；也可以从一个有依据的意外发现切入，让真实特点带来惊喜。但痛点和惊喜只是可选方法。用户明确指定了受众、场景或重点时，先围绕该诉求选择思路，不为制造戏剧性而改写方向。

遵循总 README 的顺序：`真实素材 → 宣发目标 → 叙事模式 → 品类证据 → 平台结构 → 表达语调 → 风险校验`。本文件只处理种草型的思路选择；平台、语调和完整篇章留给下游。

## 输入优先级

1. **用户诉求确定方向**：先提取本次推广对象、最想传达的价值，以及明确写出的受众、场景、卖点和限制。不要先从素材库挑一个容易写的特点，再反过来改变诉求。
2. **已勾选素材提供依据**：只看当前勾选的企业素材，优先采用与诉求相关的用户新增或上传内容；再从其他已勾选素材中选取 1–2 个可感知、可展示或可核对的细节。
3. **证据决定表达力度**：区分产品事实、企业自述、真实体验与个人评价。诉求中的“好用、耐用、划算、有效”等词是希望表达的方向，仍要检查素材能支持到什么程度。没有真实使用记录，不编造购买、试用、回购或他人反馈。

## 从 A 到 B：原初关键词如何变成四字段

逆向测试中的 A 是对作者简短宣发诉求的推测，B 是人工提炼的四字段。四类案例分别从试吃发现、按肤质挑选、按空间收纳和实地探访进入，但共同的推导过程是：

**对象与真实特征 → 谁会在意 → 在什么节点能感知或判断 → 值得分享的具体理由。**

这个理由可以是“它回应了一个麻烦”，也可以是“一个细节带来意外发现”，还可以是“它帮助人作出选择”或“它符合某种体验期待”。先确定本次诉求要强调什么，再选择最有素材支撑的一种进入方式。

### Step 1 提取原初关键词

从诉求和素材中识别：

- **对象词**：准确的产品、地点、服务或技艺名称。
- **需求词**：用户要解决的麻烦、要作出的选择，或期待获得的体验。
- **人群词**：诉求明确指定的人群；未指定时，从具体需求反推。
- **特征词**：口感、质地、结构、容量、工序、地点、活动等 1–2 项相关细节。
- **节点词**：购买、试用、食用、整理、出游等能接触该特征的合理时刻。
- **边界词**：适用条件、个人偏好、价格与活动时效，以及素材无法证明的结果。

关键词不是最终输出。先判断它们之间能否形成一条有依据的推荐思路。

### Step 2 将特征转成受众在意的理由

对每个候选特征追问：“谁在什么情境下会注意到它？它帮助对方解决什么、选择什么，或发现什么？”

- 若诉求指向**实际麻烦**，找出与麻烦直接相关的产品细节，再说明可观察的便利或变化。不能仅凭材料、结构就推出未经证实的功效。
- 若诉求指向**惊喜发现**，惊喜应来自有依据的外观、口感、质地、设计或现场体验。可表达“原来还有这种用法”一类反差，不虚构“全网没人知道”“远超同类”等比较。
- 若诉求指向**选购判断**，把多款产品或多个特点转为清楚的选择线索。系列丰富不等于人人适用，价格低也不自动等于性价比最高。
- 若诉求指向**体验期待**，用已确认的地点、活动或使用场景说明值得关注什么。没有真实体验记录时，提出观察点，不伪装成亲历感受。

### Step 3 选择一条种草切口

从以下方向中选**最回应本次诉求、最有素材依据**的一条，不同时输出多个切口：

- **麻烦得到回应**：具体困扰 → 接触产品及真实细节 → 可观察的便利。
- **发现一个亮点**：原有印象或普通期待 → 看见、尝到或用到真实细节 → 形成有边界的惊喜。
- **帮助作出选择**：正在犹豫什么 → 对照适用条件与细节 → 明确值得考虑的理由。
- **贴合体验期待**：想获得某种体验 → 接触已确认的内容 → 判断是否符合兴趣。

这些是推导参考，不是必须套用的句式。没有真实痛点就不制造痛点；特点并不意外就不强写惊喜。切口不必包含购买经历、前后对比或使用结果。

### Step 4 压缩为四个字段

- **核心宣发受众**：谁会在意这项需求或特点。优先采用诉求指定的人群；无法合理细分时填写“有相关需求的人”。
- **核心表达**：让受众记住一个具体的推荐理由，说明对象如何回应需求、帮助选择或提供值得关注的体验。不要并列堆放所有卖点。
- **内容切口**：用三个短语呈现同一条思路，如“需求或期待 → 对象与真实细节 → 便利、发现或判断”。这是选题方向，不是正文段落顺序。
- **开场钩子**：从同一切口提炼一个具体麻烦、动作、发现、反差或问题。可以有口语感和轻微情绪，但不能另开卖点或照搬参考爆款的话术。

四字段各回答不同问题，不能换词重复同一句卖点。

## 严格边界

- 只使用本次勾选的企业素材作为当前对象的事实依据。参考爆款只用于学习如何从 A 推到 B，不能继承其中的人物身份、经历、价格、功效、地点或传播成绩。
- 不虚构购买记录、使用天数、前后效果、室友或家人反馈、回购、偶遇等情节。企业账号可以用透明的品牌视角提出选择建议。
- 主观口感、肤感、审美和旅行感受不能写成所有人的统一结果。医学、安全、营养功效和比较性结论须有相应证据。
- “解决痛点”只能写到素材能够支持的便利或变化；“制造惊喜”只能基于真实细节与合理反差。不得凭空增加麻烦、稀缺性、效果或夸张排名。
- 只输出备忘录式四字段大纲，不输出分析过程、原初关键词、备选方案、正文、平台标签、购买指令或解释。
- 四字段按顺序各占一行；字段值上限依次为 **10、20、25、25 字**，合计不超过 **80 字**。汉字、字母、数字、箭头和标点均计入。

## 标准输出格式

核心宣发受众：[10字内，谁会在意]
核心表达：[20字内，单一推荐理由]
内容切口：[25字内，需求或期待→真实细节→便利、发现或判断]
开场钩子：[25字内，从同一切口进入]

## 品类补充要点

- **农产品**：从有依据的外观、口感、时令、食用方式或采收细节中寻找品尝理由。可以由真实口感形成惊喜，但产地不能自动证明品质或营养功效。
- **护肤品**：从诉求指定的肤质需求、质地、气味或使用场合中选择切口。成分存在不等于功效已得到证明，个体肤感不能扩大为普遍结果。
- **日用品**：将材料、结构或容量连接到整理、拿取、携带等具体动作。便利之处应说清；耐用、承重、安全及不伤物品等主张须有依据。
- **文旅与非遗**：从路线选择、文化兴趣或体验期待进入，用已确认的地点、活动、工序或作品支撑。活动时间与开放情况要核对，不把普通手作或古建筑未经认定就称作非遗。

## 输出前自检

- 是否先由本次用户诉求确定方向，再用当前勾选素材支撑？
- 痛点或惊喜若被采用，是否确实与诉求和真实细节相关？
- 内容切口是否只有一条思路，并保留最关键的 1–2 个细节？
- 核心表达是否给出具体推荐理由，而非“很好、必买、最值得”？
- 钩子是否与切口一致，且没有制造虚假的经历、反差或结果？
- 四字段是否分别回答“谁、为何值得关注、从哪个细节判断、从何进入”，并满足字数限制？

## 逆向测试方法

逐例只将测试输入 A 与对应的可用事实交给模型，再与人工 B 比较。重点检查：是否回应诉求、是否选对受众、推荐理由是否由真实细节推出、痛点或惊喜是否自然且有依据。允许不同措辞，不要求复刻标准答案。
