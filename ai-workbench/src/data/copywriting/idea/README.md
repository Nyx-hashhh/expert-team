# idea 阶段 从简短输入到思路大纲

`idea` 是第一次 API 调用，职责是把用户的一句话诉求与本次选中的企业素材转成简短、可编辑、能被下游直接读取的四字段思路大纲。它只做逻辑规划，不写最终文案。

## 输入合同

- 原始宣发诉求：允许只有一句话或几个关键词。
- 思路模式：故事型、种草型或品牌型，只选一个。
- 企业素材：只使用本次明确提供或勾选的事实。

平台、语调和 A/B 版本不是本阶段的必要输入，不得据此提前展开正文。

## 执行顺序

1. 可先用 [输入整理清单](task-brief.md) 区分已有事实、目标与缺失信息。
2. 读取 [从简短输入到思路大纲的实操方法论](01-methodology/from-brief-to-outline.md)，完成四字段的通用推导。
3. 进入 [02-modes](02-modes/)，只读取所选模式对应的一个文件。
4. 压缩为四个备忘录式短字段并自检。

## 输出合同

```text
核心宣发受众：[10字内；最需要这条内容的人及其处境]
核心表达：[20字内；一个由事实支撑的结论]
内容切口：[25字内；按所选模式的三步公式书写]
开场钩子：[25字内；能立即带出切口的短句]
```

四个字段应短、准、彼此有因果，字段上限依次为 10 / 20 / 25 / 25 个汉字，内容合计不超过 80 个汉字，便于用户直接修改和“一键填入”第二阶段。若产品或品牌没有明确受众指向，核心宣发受众填写“泛消费人群”；不得为了显得具体而虚构年龄、职业或身份。

## 阶段边界

- 禁止输出完整标题、正文段落、五幕成文、分镜、标签或平台排版。
- 禁止抒情、堆形容词、编造体验、用户证言、数据或品牌历史。
- 禁止生成 A/B 两套思路；A/B 版本属于 `post` 成文阶段。
- 禁止读取未选模式或无关品类的规则。
- 发现信息不足时，保留最小可行思路并标明需核实的事实，不用想象补齐。

完成后，将“所选模式 + 四字段思路 + 相关真实素材”交给 [post 阶段](../post/README.md)。
