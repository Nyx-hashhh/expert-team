# 从简短输入到思路大纲的实操方法论

本文用于第一次 API 调用。目标不是把输入扩写成长文，而是把“一句话诉求 + 已选企业素材”推导为四个短字段，让用户能快速确认，并让第二阶段准确接力。

## 一 先把输入分成事实 目标 缺口

建立只在推理过程中使用的三栏清单：

- **事实**：企业素材中可以直接核验的产品、品牌、场景、参数、工艺、服务或历史信息。
- **目标**：用户明确想让受众知道、相信、尝试或购买什么。
- **缺口**：输入没有提供、但若写入就会构成推测的信息。

只允许从“事实”推导，不得把“目标”误当成已经被证明的事实。缺失信息不补造；确有必要时在结果后用“待核实”标记，但不得让标记挤占四字段主体。

## 二 只加载一个思路模式

根据用户选择读取一个模式文件：

- **故事型**：寻找“谁在什么具体处境中遇到什么问题，产品或品牌如何参与变化”的因果链。
- **种草型**：寻找“谁因什么需要做选择，哪些事实能帮助其判断是否适合”的决策链。
- **品牌型**：寻找“品牌属于什么品类，凭什么形成差异，这个差异给用户什么价值”的信任链。

不得同时混读三个模式后拼接结果。模式只决定推导角度，不允许在本阶段展开为完整故事、体验正文或品牌宣言。

## 三 推导核心宣发受众

按以下顺序判断：

1. 从用户诉求中找明确对象。
2. 从产品使用条件、购买动机和真实场景中找“最需要这条信息的人”。
3. 用“人群 + 当前处境或需求”表达，避免只写宽泛年龄标签。
4. 没有可靠指向时填写“泛消费人群”，不猜职业、收入或身份。

建议控制在 8 至 20 个汉字，最多保留两类高度相关人群。

## 四 推导核心表达

使用这条最小因果链：

`真实产品或品牌特征 → 对使用或选择产生的具体影响 → 受众应记住的一个结论`

先列出不超过三个候选事实，再选择与用户目标关系最直接、证据最完整的一项作为主轴。核心表达只保留一个结论，避免把价格、品质、情绪价值和品牌使命并列成口号。

建议控制在 18 至 35 个汉字。不得使用“最好、唯一、必买、零风险”等无证据绝对表述。

## 五 推导内容切口

内容切口不是正文结构，而是进入核心表达的那个具体观察角度。按所选模式完成一次推导：

- 故事型：从受众对应的人物、真实场景和关键阻力中，选择最能体现变化的一刻。
- 种草型：从高频麻烦、选择标准或使用场景中，选择最能帮助判断的一项。
- 品牌型：从品类认知、差异事实或可信行动中，选择最能建立信任的一项。

切口必须能用企业素材支撑，并与核心表达直接相连。不要在本阶段设计 A/B 两种切口，也不要写平台热词。

建议控制在 20 至 45 个汉字，写清“从什么场景或矛盾进入”。

## 六 推导开场钩子

把内容切口压缩为一个能立即让目标受众进入问题的短句：

1. 先指出具体场景、反常细节、真实疑问或关键选择。
2. 让钩子自然通向核心表达，不使用与正文无关的夸张悬念。
3. 删除空泛前缀，如“你敢相信吗”“家人们谁懂”“震惊了”。
4. 钩子只提出进入点，不在一句话里塞完全部卖点。

建议控制在 12 至 28 个汉字。不得捏造经历、结果、稀缺性或他人评价。

## 七 压缩为固定四字段

最终只输出：

```text
核心宣发受众：[8 至 20 个汉字；无明确指向时写“泛消费人群”]
核心表达：[18 至 35 个汉字；一个有事实支撑的结论]
内容切口：[20 至 45 个汉字；一个具体场景、矛盾或选择]
开场钩子：[12 至 28 个汉字；能直接带出切口的短句]
```

输出采用备忘录式短句，不解释推理过程，不加平台、语调、标题、正文、标签、分镜或 A/B 版本。

## 八 出口自检

- 四字段是否分别回答“对谁说、说什么、从哪里进入、第一句怎么进入”？
- 核心表达是否由至少一项已知事实支撑？
- 内容切口是否服务于核心表达，而不是另起一个主题？
- 开场钩子是否承接切口，且没有夸张或虚构？
- 是否误写成正文、抒情段落、五幕故事、体验复盘或品牌宣言？
- 是否读取了未选模式、无关品类、平台或语调规则？

任一项不通过，先删减和收束，不通过扩写解决。

## 九 示例

### 示例一 京都柑橘味护手霜

输入：`京都产护手霜，柑橘味，适合旅行者购买或作纪念品，突出当地特色。`

```text
核心宣发受众：京都旅行者与柑橘香气爱好者
核心表达：兼具日常护手用途与京都伴手礼记忆点
内容切口：从旅行结束前挑选一件既实用又有当地特色的纪念品进入
开场钩子：离开京都前，别只带走冰箱贴
```

### 示例二 高山春茶

输入：`高山春茶新品，清明前采摘，想突出办公室自饮和送礼品质感。`

```text
核心宣发受众：重视茶味与送礼体面的上班族
核心表达：明前高山鲜叶让日常自饮和春季送礼都有明确品质依据
内容切口：从办公室续杯与春日拜访共用一罐茶的双重场景进入
开场钩子：一罐茶，先陪你上班再替你见客
```

## 十 用逆向推导调试规则

方法论文件需要迭代时，使用同一套闭环：

1. 为当前品类找到一篇真实、有效的代表性内容。
2. 人工剥离修辞，把它拆成理想的四字段输出 B。
3. 反推作者最初可能拥有的简短诉求与真实素材，形成测试输入 A。
4. 对比 A 与 B，写清人类补上的推导步骤，并把可复用部分补入对应模式规则。
5. 必须在工作台网页端用 A 实测，比较机器输出与 B 的逻辑质量。
6. 对差距归因；把缺失推导补成正向规则，把重复错误补成负向约束，再次测试。

每次只修正能够解释差距的一条规则，避免无限扩写。故事型、种草型、品牌型应分别覆盖农产品、护肤美妆、日用品、文旅或非遗等品类测试；运行时仍只读取当前任务相关文件。
